# Combat presentation and render budget

Compared with the sibling COD4 checkout on October 16, 2026. The starting
COD2 revision was `3a05a50bc564854ceeecbb0520fa62123a6a5471`.

## What transfers within the existing budget

COD4's `cg_weapons.cpp` submits segmented, potentially wiggling tracer beams.
Its `rb_postfx.cpp` uses downsampled render targets and multiple full-screen
filters for depth of field. COD2's browser renderer uses the fixed-function
DX7 material path. Reproducing COD4's full post-processing, shadow maps and
normal/specular material pipeline would require additional rendering work.
They are not part of this change.

COD2 already had muzzle lights, tracers, fog, baked shadow filtering, contact
shadows, weapon focus, anisotropic filtering, sprint and controller controls.
Those are not new features introduced here.

| Change | Visible or gameplay result | Work budget |
| --- | --- | --- |
| Weapon clarity | ADS retains the original weapon and hand texture detail, including the rear receiver and sights | One unmodified base sample shared with flash illumination. Removed blur calculations, uniform uploads and viewmodel tracking; no framebuffer, extra texture or screen pass |
| Tracer ribbons | Off-center parallel shots retain a camera-facing width; tails taper and fade toward the muzzle | Same four vertices, material, spawn probability, speed, distance and lifetime; empty beams are skipped |
| Bullet near-miss sound | Disabling tracer visuals no longer suppresses incoming bullet audio | Original sound selection and distance checks; no new default sound instances |
| FX light selection | A nearby muzzle flash or broad explosion can replace a weaker distant light instead of being dropped by arrival order | Four default light slots and the same GPU arrays; bounded CPU ranking at effect submission, without visibility traces |
| Light/shadow handoff | Existing lighting and contact shadows use a shared camera transform cache | One WebAssembly-to-JavaScript call per draw replaces two; inactive channels are invalidated correctly when the view changes |
| Fixed-function texture attributes | Materials retain their UVs without invalid attribute submissions | Respect both sampler and vertex-attribute limits; skip inactive coordinate attributes while retaining texture matrix updates |

The initial material mip approximation was removed after visual feedback: it
discarded texture detail without softening the silhouette or illumination,
making ADS look lower quality. Both hip and ADS now use the authored texture
footprint and existing filtering. No replacement artificial blur is enabled.

COD4's `cg_weapons.cpp` interpolates weapon-specific `adsDofStart/adsDofEnd`
with the aiming fraction. `rb_postfx.cpp` computes viewmodel and scene depth
equations, resolves the rendered scene, downsamples, applies Gaussian/near-CoC
filters and composites it. That is optical image filtering, not a texture mip
downgrade. Reproducing those passes would add GPU work, so this correction
restores sharpness instead of claiming to reproduce COD4 DOF at no cost.

The FX light ranking uses brightness divided by one plus squared distance in
units of the light radius. Ties retain earlier lights. It does not perform
occlusion tests. The normal browser limit remains four; no effect textures,
particle pools, LOD distances, output resolution or gameplay rules are expanded.

## Validation of the earlier graphics iteration

The measurements below describe the earlier mip-filtered iteration, retained
as evidence for the other changes. They are not measurements of the final
weapon-clarity correction; its separate checks are described below.

The Emscripten 3.1.64 client compiled and linked. The existing full static suite
passed; final targeted checks also exercise the changed linked shader generator,
attribute limits, transform cache, tracer geometry and FX light selection.
The linker still reports existing compatibility-stub signature warnings.

- `scripts/test-combat-presentation.py`: production C functions under
  ASan/UBSan; 1,512 translated/off-axis tracer geometries, zero-length/end-on
  cases, near-miss audio with visuals off, repeated selection of nearby lights,
  large explosion influence, all limits from zero to 32 and nonfinite input.
- `scripts/test-web-point-lights.cjs`: scene/view transforms and uniform
  caching, including camera changes while either lights or shadows are inactive.
- `scripts/test-emscripten-gl.cjs`: actual linked functions, nine combinations
  of texture/attribute limits and 600 draws with sparse coordinate attributes.
- The earlier `scripts/test-web-focus.mjs`: real WebGL2 shader compilation and pixel reads,
  both ordinary and matrix UVs, central sharpness, peripheral blur, alpha,
  distant sharpness and world isolation. The shader patch also passed repeat
  application and upgrade from the previous generated shader.

The real-canvas check on Chrome/ANGLE/Apple M4 passed every pixel assertion.
Its six alternating shader-only captures at 1280×720 measured GPU time per
draw of 0.0344/0.0280/0.0181/0.0215/0.0268/0.0233 ms in
before/after/after/before/before/after order. Sample ranges overlap; this is
evidence of reduced texture sampling, not a game FPS speedup claim.

In matched Carentan loading/menu checks, the baseline emitted 256 WebGL invalid
attribute warnings before Chrome stopped reporting them. The corrected client
emitted none. Neither run raised a JavaScript exception.

Four additional Carentan captures ran in before/after/after/before order, with
the isolated server restarted and the map recreated before each run. Each used
one client, no bots, the Thompson, position `(0 1000 52)`, yaw zero, centered
pitch, 1280×720 output and the existing antialiasing setting. Every reported
window contains 600 rendered frames; captures followed 12 seconds each of
standing and aiming. All eight windows maintained approximately 60 FPS.

| Configuration | Main-thread mean range (ms) | Frame p95 range (ms) | GPU query mean range (ms) |
| --- | ---: | ---: | ---: |
| Before, hip | 6.58–6.69 | 17.24–17.66 | 2.89–5.42 |
| After, hip | 6.51–7.21 | 17.57–17.60 | 2.54–4.27 |
| Before, ADS | 6.95–7.41 | 17.22–17.63 | 2.75–5.09 |
| After, ADS | 6.82–7.54 | 17.55–17.57 | 2.37–4.80 |

These overlapping ranges do not establish a small CPU/GPU speedup or strict
timing equivalence. Draw counts also varied between windows despite matching
camera positions. The asynchronous GPU queries include submission gaps and
other activity on this shared workstation can affect scheduling. The results
show no observed FPS loss in these tests, rather than zero added cost on every
device or a precise speedup. Earlier captures without restarting the room are
retained as functional evidence, not included in this comparison.

The candidate was also observed firing, aiming, reloading and moving in the
local network match. Fired shots consumed ammunition; movement changed the
reported position. The firing window included an empty magazine and must not
be presented as a sustained-fire benchmark. Crowded combat, killcam and the
other maps were not revalidated for these changes. Existing native startup
warnings about `mpflag_none` and shellshock dvars appeared in both builds;
the candidate produced no JavaScript exceptions or WebGL errors.

Local raw evidence and screenshots are in ignored `out/quality-qa/`.
`comparison.json` contains the four clean captures, and `build-hashes.json`
identifies the retained baseline and final candidate bundles. The test server
used a separate Docker Compose project and port 18092 and was removed after
validation. Production containers and the existing player session were not
replaced. The updated browser bundle is built locally, not deployed.

## Weapon-clarity correction

The final correction removes the material DOF approximation throughout the
browser path: shader bias/mask calculations, blur uniforms and their uploads,
the viewmodel draw classification, the per-frame ADS value and its resets.
The shared lighting/shadow camera cache and original ADS poses are retained.
Previously generated JavaScript can be upgraded and repatched idempotently.

The Emscripten 3.1.64 client rebuilt successfully and the complete
`scripts/test-static.sh` suite passed on the final linked bundle. The combined
respawn staging package and its 4,745 private asset entries also passed their
package and asset checks. Existing compatibility-stub linker warnings remain.

The updated `scripts/test-web-focus.mjs` passed 102 real WebGL2 checks on
Chrome/ANGLE/Apple M4. It reproduces the previous detail loss, then verifies
pixel-exact recovery of the original sharp samples at four eye depths and four
ADS values, in model/world and regular/matrix UV variants. Flash illumination
matches the original sharp materials and alpha is preserved. The final linked
shader has no blur uniform, additional texture sample or post-process pass.

The six alternating 1280×720 shader captures measured approximately
0.0425/0.0231/0.0268/0.0426/0.0425/0.0418 ms per draw in
before/after/after/before/before/after order. This is a synthetic shader check,
not a general game speedup measurement. Compilation and other work ran on the
same machine; these samples cannot establish universal timing equivalence.

In isolated Carentan matches, both the baseline and corrected client maintained
about 60 FPS at 1280×720 in the captured hip/ADS windows (600 frames each).
The final ADS capture visibly restores the Thompson receiver's metal grain
and the original hand/sleeve detail. Camera direction differed between the
two ADS captures, so their CPU/GPU timings are functional evidence rather than
a matched performance comparison. Both runs had zero JavaScript exceptions
and the same pre-existing `drawElements: no buffer is bound to enabled
attribute` WebGL warning. That separate warning is not fixed by this change.

The baseline immediately before this correction, build hashes, screenshots,
browser logs and pixel results are retained in ignored
`out/weapon-clarity-qa/`. The separate `out/respawn-qa/site` bundle was refreshed
with this client and the previously staged respawn assets. Live containers and
their private asset archives were not replaced.

To repeat the shader pixel comparison, retain the mip-blur baseline `cod2.js`
before building, then run:

```sh
CHROME_EXECUTABLE=/path/to/chrome node scripts/test-web-focus.mjs \
  /path/to/baseline/cod2.js out/cod2-wasm-core/site/cod2.js \
  /path/to/playwright/index.mjs out/web-focus-qa
```

Hardware, browsers and multiplayer effect density vary. No universal zero-cost
or minimum-FPS guarantee follows from these local checks.
